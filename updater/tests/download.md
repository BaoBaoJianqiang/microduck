# tests/download.rs 文件解析

## 文件位置

`d:\microduck\updater\tests\download.rs`

## 定位

HTTP 下载层测试，基于真实本地服务器（axum 而非 mock——被测行为就是 HTTP 语义）。

## 关键关注点（按伤害程度排序）

1. **断点续传不得损坏。** 忽略 Range 的服务器返回 200 整包，追加到部分文件会产生看似合理但长度错误的文件（哈希会抓，但重试浪费且误导）
2. 进度到达调用方，否则 app 进度条卡住
3. 失败说可操作的话

## 测试用例

- 服务器支持 Range → 206 续传正确
- 服务器忽略 Range → 返回 200，下载器处理（不损坏）
- 进度回调按 gap 节流
- 网络失败重试
- 不完整响应

## 关键摘要

download.rs 用 axum 本地服务器测试 HTTP 下载层：验证 Range 续传正确性（忽略 Range 的服务器不得损坏文件）、进度节流、失败重试；用真实 HTTP 语义而非 mock。
