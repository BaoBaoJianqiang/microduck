# `link.rs` 文件解析 —— 无线电与可测试逻辑之间的接缝

## 1. 文件定位

- 路径：`src/link.rs`
- 角色：定义 `Link`，作为无线电后端与 `session` 会话逻辑之间的**接缝（seam）**。
- 核心立场：刻意**不使用 trait**。

## 2. 为什么是两个 channel 而不是 trait

- 一个 `GattLink` trait 必然需要异步 `recv` 和异步 `send`，而会话循环要同时等待两者；
- 这会逼迫两种坏选择之一：要么把链路拆成带关联类型的读写两半，要么在 `select!` 里与借用检查器搏斗；
- 两个 channel 加一个普通结构体就能表达同样的抽象，且没有上述麻烦；测试中手工构造一个即可，无需实现任何 trait。

后端要做的全部工作：

1. 接受连接；
2. 把入站分片喂进 `inbound`；
3. 把 `outbound` 上出现的任何内容写回中心设备；
4. 中心设备离开时丢弃 channel。

两个 channel 之间发生的一切都属于 `session`，它永远不知道自己背后是否真的有无线电。

## 3. 常量 `QUEUE: usize = 512`

任一方向上允许排队的分片数。其容量是**正确性要求**而非调参选择：

- 必须保证"一条最长的入站行永远不必阻塞发送"；
- 无线电后端在收到分片并入队之间**不能 await**：BlueZ 把每次写分发为独立任务，任何让出点都可能让两个分片交换位置，而乱序分片会静默损坏请求；
- 历史教训：3 片中的第 2 片最后到达，曾产生 `{"id":1,"jsonrpc":"2.info","params":{}}`——合法 JSON、缺字段、解析错误却归咎客户端；
- 因此队列要深到同步 `try_send` 在合法流量上不会失败：`QUEUE * 20 >= framing::MAX_LINE`，其中 20 是 BLE 保证的最小载荷；
- 超出容量的泛洪得到干净的 ATT 错误（写失败可恢复，客户端会重发），而不是被丢弃的分片（丢片不可恢复，会重组出错误内容）。

## 4. 结构体 `Link`

表示一个已连接的中心设备，含四个字段：

| 字段 | 类型/方向 | 含义 |
| ---- | --------- | ---- |
| `inbound` | `mpsc::Receiver<Vec<u8>>` | 中心设备写入请求特征值的分片，按到达顺序；断开时关闭 |
| `outbound` | `mpsc::Sender<Vec<u8>>` | 要通过响应特征值通知出去的分片 |
| `mtu` | `usize` | 本连接协商出的可用通知载荷 `ATT_MTU - 3` |
| `peer` | `String` | 中心设备地址，仅用于日志 |

关于 `mtu`：每会话读一次而非每条消息读一次——中心设备可能重新协商，但不会在一行中途重协商；反复读取会让同一行被两种不同方式分片。

关于 `peer`：**绝不用于授权**。BLE 地址极易伪造，授权靠的是配对（`architecture.md` §4.2）。

## 5. `Link::pair()`

```rust
pub fn pair(mtu, peer) -> (Self, Sender<Vec<u8>>, Receiver<Vec<u8>>)
```

- 建立两条容量为 `QUEUE` 的 mpsc channel：`(to_robot, inbound)` 与 `(outbound, from_robot)`；
- 返回三元组：`Link` 本体、调用方用来模拟"中心设备写入"的发送端、调用方用来读取"机器人通知"的接收端；
- 被测试以及（注释提到的）`--fake` 使用。

## 6. 编译期不变量检查

文件末尾有一个 `const _: () = assert!(...)`：

```rust
const _: () = assert!(
    QUEUE * 20 >= crate::framing::MAX_LINE,
    "QUEUE * 20 must be at least framing::MAX_LINE ..."
);
```

- 选择编译期检查而非运行时测试：这是两个常量之间的关系，不存在"运行时为真、构建时为假"的情况；
- 它是无线电后端敢于使用同步 `try_send`（不 await）的底层保障——一旦容量关系被破坏，编译直接失败。

## 7. 本文件要点小结

1. 用"两个 channel + 普通结构体"取代 trait，简化 `select!` 并便于测试；
2. `Link` 四字段：入站接收、出站发送、MTU、对端标识（仅日志，不授权）；
3. `QUEUE = 512` 保证最长行（8 KiB，按 20 字节最小分片）也能用非阻塞 `try_send` 全部入队；
4. 不在接收分片与入队之间设置 await 点，杜绝分片乱序；
5. 容量关系用编译期 `const assert!` 强制锁定。
