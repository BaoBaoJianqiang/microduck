## 二、核心设计：PIN 检查在链路层之上

### architecture.md 的要求

- §4.2 说 BLE 授权是"物理存在 + 配对"。
- §7 要求携带 wifi 凭据的 characteristic 必须配对并加密。
- 两者都成立——但 PIN 检查住在**链路层之上**，这是被迫的而非选择的。

## 三、为什么 BLE 不能做这个

### 第一次设计：机器人用存储的 PIN 回答 BlueZ 的 passkey 请求

**在无头机器人上无法工作**：
- 在 LE passkey entry 中，一方*显示* passkey，另一方*输入*它，角色跟随每方声明的 IO 能力。
- 实现 `request_passkey` 声明"此设备可以输入"，因此 macOS 采取显示角色，生成随机六位数代码，等待有人把它输入没有键盘的机器人。

### 反向也失败

- 用 `DisplayPasskey`，机器人采取显示角色，但 **BlueZ 生成 passkey**——规范让显示方随机选择。
- 印在贴纸上的固定 PIN 根本无法在 BLE passkey entry 中表达。

## 四、方案：just-works 配对 + 传输层检查 PIN

### 配对是 just-works

- 所有 agent handler 为 `None`，BlueZ 读取为 `NoInputNoOutput`。
- 因此链接加密但**不**认证。
- RPC characteristic 上的读需要加密，这就是触发绑定的原因。
- 然后 `btd` 在客户端通过 `system.authenticate` 证明 PIN 之前什么都不服务——这就是为什么该调用由传输层回答而非转发。

### 代价（坦率陈述）

- PIN 穿过加密但未认证的链接，因此在*配对时刻*在场的攻击者可以捕获它。
- 替代方案是完全没有认证，或 BlueZ 几乎不支持且没有手机应用驱动的带外 QR 流程。
- 对于家庭中的机器人，这是更好的权衡，并且可以在不接触传输层的情况下重新审视，因为检查现在是我们的而非规范的。

### 出厂 PIN

- **出厂 PIN 是 `000000`，每个人都可以在此仓库中读到。**
- 因此开箱即用，这证明物理存在而已，与 just-works 配对给出的保证相同——区别在于机制、存储和六位数契约都已就位，因此使其成为真正的秘密是配置变更而非重新设计。
- 印在机器人下方的每机器人 PIN 才是把这变成安全的东西，那是 `updater-design.md` §5.7 的每设备状态。

## 五、没有配对窗口，这是决定的而非推迟的

- 机器人在广告时随时可配对。
- 物理按钮按住窗口是通常的答案，被考虑并拒绝：
  - **每机器人 PIN 已经携带窗口会添加的属性。** 如果 PIN 唯一且印在机器人下方，知道它需要物理访问——能读贴纸的人也能拿起机器人。
  - 窗口只会防御出厂默认仍在位时范围内的人，而答案是真正的 PIN，不是按钮。
- 按钮会额外带来：可见的同意时刻、PIN 丢失时的恢复路径、贴纸被拍照时的纵深防御。v1 都不需要，每个都是以后可添加的。

### 安全完全依赖 PIN 是每机器人的

- 这使它成为配置义务而非软件义务：必须有东西生成它、打印它并记录打印了什么。
- 机器人现在确实有每设备身份——`configd::identity` 从 SoC 序列号派生——但 PIN 不能从它派生：
  - 身份是*发布的*，在范围内任何人都可以收集的广播中，因此从它计算的 PIN 在推导已知的那一刻就是公开的。
  - 只有名字挂在身份上。
  - 秘密仍然必须生成、打印和记录。

### 仍开放的较小项

- **没有绑定管理。** 每个配对的手机保持配对，没有东西撤销一个；`bluetoothctl untrust` 是手动逃生，直到有 API。

## 六、常量与函数

### `PIN_TIMEOUT = 3 秒`

- 等待 configd 用 PIN 回答的时间。
- 短：BlueZ 正持有配对交换打开，手机在我们决定时显示旋转器。如果 configd 不能在这么长时间内回答，它就不会回答。

### `pin(config_socket: &Path) -> Result<PairingPinResult, String>`

- 向 configd 请求配对 PIN。
- **每次配对请求获取**而非启动时缓存，因此 `robotctl system set-pin` 在下一次配对时生效而非下一次重启。
- 在已经需要人类几秒钟的交换中，一次 socket 往返。
- **整体返回而非解析**：比较在字符串上，因为 `000042` 和 `42` 是不同的 PIN，数字解析会使它们相同。
- `is_default` 随它返回，因此调用者可以大声说出出厂 PIN 认证了任何读了此仓库的人。
- **PIN 从不记录。** 它今天几乎不是秘密，但每机器人的 PIN 意味着是，而日志是错误的地方。
