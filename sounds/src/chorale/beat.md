# chorale/beat.rs 文件解析

## 文件位置

`d:\microduck\sounds\src\chorale\beat.rs`

## 核心设计决策

在没有共享时钟的情况下让几只鸭子保持同步。四个机器人唱和弦必须在**约 ±20 ms**内对节拍达成一致——这个数字来自：一个同意到毫秒的合奏听起来像一个管风琴，所以几十毫秒的散布是*有意添加*的，同步只需紧到不淹没它。

**不做**：同步时钟并约定开始时间。板卡没有 RTC 协议也没有 NTP，建立偏移意味着连接、配对和一个 `btd` 没有的中央角色蓝牙客户端。

### 指挥是一个信标

没有人共享时钟——他们共享一个**节拍**。指挥鸭子在 BLE 广播中放一个节拍计数器，每音乐节拍递增一次。其他人被动扫描，*新计数器值的到达就是强拍*。无需时间戳比较、偏移估计、连接、配对：被动扫描是全部无线电需求。

### 为什么无线电抖动不会毁了它

空口时间是微秒；误差是**广播时隙**。`btd` 故意将时隙间隔设为 100–150 ms（一根天线承载 BLE、手柄和 wifi）。所以跟随者在 50 ms 窗口内的某处听到每个节拍，且——关键——*每拍独立*。

两件事将其变为 ±6 ms：
1. 指挥将自己的播放延迟 `SLOT_MEAN_S`（窗口中间），使其方向与其他人相同。
2. 跟随者不追逐单个节拍，而是在滑动窗口上平均*相位*（`Follower::WINDOW=24`），独立抖动随窗口平方根下降。

**节奏不被估计，这是修复而非捷径**。第一版通过 (beat, arrival) 拟合直线并从斜率读节奏，实测更差：在最新点（窗口边缘）评估的直线拟合携带约四倍于窗口中心的误差。保持周期为乐谱节奏、仅平均相位完全移除斜率项，误差降至三分之一。

### 无线电停止时

继续唱。听不到任何东西的跟随者保持最后相位并按乐谱节奏继续——晶振精度，每分钟毫秒级——指挥重现时接回。

## 常量分析

- `SLOT_MEAN_S = 0.125` —— `btd` 使用的广播时隙窗口（100–150 ms）的中间。指挥延迟自己的播放此量。

## 类型与函数分析

- `Conductor` —— 持拍的鸭子。故意简单：计数节拍并说何时把每个放到空中。不知道也不在乎是否有人在听。
  - `new(bpm, now)`
  - `due(now) -> Option<u64>` —— 下一个应该上空中的节拍（仅在节拍实际翻转时返回 Some）。
  - `position_beats(now) -> f64` —— 指挥在乐谱中的位置，比自己的节拍计数器落后 `SLOT_MEAN_S`。
  - `wire_beat() -> u8` —— 当前在空中的节拍，作为回绕的字节。
  - `beat() -> Option<u64>` —— 到目前为止交给无线电的节拍数（解绕）。

- `Follower` —— 锁定到他人节拍的鸭子。仅持有一个数：指挥节拍 0 落在何时，在最后 `WINDOW` 拍上平均。节奏来自乐谱。
  - `WINDOW = 24` —— 相位平均的拍数。50 ms 窗口标准差 ~14 ms/拍，24 拍降至 ~3 ms，两个独立跟随者 ~4 ms。
  - `OUTLIER_S = 0.20` —— 残差超过此值的不是节拍（排队的扫描或重读的陈旧广播），丢弃。
  - `new(bpm)`
  - `observe(beat: u8, at: f64)` —— 仅在计数器变化时调用。
  - `unwrap(beat: u8) -> f64` —— 将回绕字节还原为单调递增节拍数。
  - `refit()` —— 重新平均相位。
  - `locked() -> bool` —— 至少 4 拍后可唱（一拍的误差栏是整个时隙窗口）。
  - `position_beats(now) -> Option<f64>` —— 现在应在乐谱的哪里。
  - `spread_s() -> Option<f64>` —— 相位估计的散布（诊断：健康锁定几毫秒，数百毫秒意味着听到非指挥节拍）。

## 单元测试描述

- `a_whole_quartet_agrees_within_the_ensemble_budget` —— 整个四重奏（1 指挥 + 3 跟随者）通过各自独立的 50 ms 时隙抖动后，任意两跟随者最大偏差 < 20 ms，指挥与跟随者 < 20 ms，每个锁定的 spread < 20 ms。
- `the_fit_averages_the_jitter_down` —— 平均机制可见：一拍 ~±25 ms，满窗口个位数毫秒。
- `the_beat_counter_wraps_without_the_music_jumping` —— 节拍计数器回绕（>4 分钟）时音乐不跳。
- `silence_from_the_conductor_is_not_silence_from_the_duck` —— 指挥消失后继续唱，重现时无跳变接回。
- `an_outlier_is_dropped_rather_than_averaged_in` —— 半秒离群值丢弃而非平均。
- `a_follower_waits_before_it_sings` —— 跟随者在 4 拍前不唱。
- `the_conductor_counts_beats_and_not_polls` —— 指挥每拍递增一次，不随广播重复递增。

## 关键摘要

beat.rs 实现了无共享时钟的多鸭同步：指挥在 BLE 广播中放节拍计数器，跟随者被动扫描并在滑动窗口上平均相位。节奏不被估计（固定为乐谱节奏）避免了斜率估计误差。整个设计的论断（四重奏在 ±20 ms 内达成一致）被一个模拟 50 ms 时隙抖动的测试验证，无需真实无线电。
