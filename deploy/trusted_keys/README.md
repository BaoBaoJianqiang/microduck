# 可信公钥

机器人的信任锚点。`scripts/install.sh` 会把这里的文件复制到 `/etc/robot/trusted_keys/`——也就是 [`../updater.toml`](../updater.toml) 里的 `trusted_keys_dir`。一个构件只要其签名能对上这里**任意一把**密钥，就会被接受。

| | |
|---|---|
| `release-1.pub` | 如今签署所有发布版与晋升的那把 |
| `release-2.pub` | 若 CI 或 `release-1` 失守，第一把轮换目标 |
| `release-3.pub` | 最后手段；它的私钥半永远不该碰联网的机器 |

**三把密钥都从第一份镜像就带上，这正是全部意义所在。** 机器人只能对烧进它里的那套密钥做验证，所以一台所持密钥的私钥半后来丢失或泄漏的机器人，无法空投一把替换密钥——只能手工重刷。现在就把备用密钥发出去是免费的；事后补装是不可能的。保管制度见 [`../../docs/project/ci-setup.md`](../../docs/project/ci-setup.md)。

**公钥不是秘密。** 把它们提交进仓库是正确且有意为之的：它们恰恰是必须公开、才能让任何人验证我们签名的东西。私钥半放在 `~/.duck-keys` 和密码管理器里，且只有 `release-1` 的私钥在 CI 里。

**`team.dev.pub` 刻意不在这个目录里。** 信任开发密钥的机器人会安装团队里任何人构建的任何东西。它只该出现在一块开发板的 `trusted_keys_dir` 里，与那块板本地 `updater.toml` 里的 `allow_dev_keys = true` 搭配——绝不放这里，因为这里的东西每台机器人都会拿到。它提交在 [`../dev-key/`](../dev-key/)，那里没有任何东西默认安装它。

## 添加一把轮换密钥

生成它，把 `.pub` 放进这里，机器人下次安装时就会拿到。注意这个不对称性：一把*新*密钥只对在它加入之后烧录镜像的机器人成为可信，所以轮换保护的是舰队的未来，救不了已经在外的机器人。这正是备用密钥要预先存在的原因。

```bash
cargo xtask keygen --kind release --name release-4 --out ~/.duck-keys
```
