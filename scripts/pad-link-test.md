# pad-link-test.sh

## 文件位置

`d:\microduck\scripts\pad-link-test.sh`

## 核心设计决策

该脚本测量游戏手柄与机器人之间蓝牙链路的可靠性。

- **测量两种不同的失败方式**：
  1. **断开（drop）**：设备消失，`padd` 记录"pad gone"，robotd 的 deadman 停止机器人。从与 gilrs 相同的证据计数：事件节点是否存在。
  2. **停滞（stall）**：连接保持但报告停止到达几百毫秒。`padd` 轮询最后已知摇杆值并以 50Hz 持续发送，robotd 看到新鲜意图，deadman 永不触发，机器人用过期指令行走。这就是脚本读取原始事件流而非仅监视断开的原因。
- **必须移动摇杆**：evdev 设备在无变化时不发送任何东西，桌上静止的手柄与停止投递的链路无法区分。超过 `IDLE_MS` 的静默被分离出来不算停滞——链路还在但这么长时间静默只能是摇杆静止。
- **三个阈值有编译副本**：在 `duck_ipc_proto::pad_link` 中，`robotctl monitor` 的实时手柄块从中读取。故意两份副本：此脚本必须能在无编译代码的板端运行（被 scp 上去）。两者必须一致。

## 常量/参数分析

### 阈值常量

| 常量 | 值 | 说明 |
|---|---|---|
| `DEADMAN_MS` | `500` | robotd 的 deadman 将速度归零的点（来自 `safety.deadman_ms` 默认值）。超过此值的停滞不是延迟抱怨，是机器人停止 |
| `NOTABLE_MS` | `100` | 低于此值停滞对驾驶员不可见；高于此值机器人感觉粘滞。与 deadman 分开报告，因为是相同原因的不同抱怨 |
| `IDLE_MS` | `5000` | 超过此值静默是操作员而非无线电。链路停止投递这么久会触发 supervision timeout 并断开，而断开单独计数。5 秒空洞且链路还在意味着摇杆静止 |

### 命令行参数

| 参数 | 说明 |
|---|---|
| `--seconds N` | 观察时长，默认 120 |
| `--mac ADDR` | 多个手柄连接时指定哪个 |
| `--history` | 不测量，从 padd 日志统计已有断开 |
| `--since WHEN` | `--history` 回溯范围，默认 -7d |

### 退出码

- 0：测量运行完成
- 1：无法运行

## 核心逻辑

### 预检查

- 蓝牙总线上必须有带 joystick handler 的设备（`pads_on_bus`）。
- 只有 event 节点不够：Xbox 手柄注册多个输入设备（手柄 + 媒体键键盘），取第一个 event 节点会测到从不发送的媒体键。
- 32 位用户land 或无 `od -w` 时只计断开不测节奏。

### watch 循环

- 用 `od -A n -t u8 -w24 -v` 读取 evdev 原始事件流（24 字节 = 8 秒 + 8 微秒 + 8 type/code/value）。
- 每轮重新解析事件节点路径（手柄重连可能变号）。
- 设备消失时计断开，重新出现时记录恢复时间。
- 用 `/proc/uptime`（厘秒，单调时钟）计时，避免 NTP 调整墙钟干扰。

### 节奏统计（awk）

- 只统计 SYN_REPORT（type 0, code 0, value 0，即第三列全零），而非每个事件（否则摇杆每个轴单独计数）。
- SYN_DROPPED（type 0, code 3，值 196608）表示本读取器跟不上，与无线电无关，单独报告。
- 间隔分类：> IDLE_MS 为 quiet（摇杆静止），否则为 driving；> NOTABLE_MS 计数，> DEADMAN_MS 计数。

### 判定

- 无报告到达：链路不工作或摇杆没动。
- driving 时间 < 10s 且无断开：数据不足，无法判定。
- 无断开、无 deadman 超限、无 notable 超限：链路保持。
- 无断开、无 deadman 超限但有 notable 超限：机器人感觉粘滞。
- 有断开或 deadman 超限：链路不稳定，每次都会停止机器人。

## 关键要点总结

1. 读取与 gilrs 相同的 evdev 节点，不独占设备，可在机器人被驱动时测量。
2. 必须持续移动摇杆，否则静默无法与停滞区分。
3. 事件节点路径每轮重新解析，处理重连后编号变化。
4. 判定基于实际驱动时间而非整个窗口，避免暂停时误报。
5. `--history` 模式从 padd 日志统计断开，并给出内核原因（0x08 = supervision timeout，0x13/0x16 = 手柄关机非故障）。
