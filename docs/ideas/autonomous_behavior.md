# 自主行为栈 —— 它继承什么，以及等待它的想法

大脑是[对等审计]（§03）中最大的未追踪缺口：运行时的 `autonomous.rs` 在守护进程中无处存在，且尚无设计文档负责它。本文件是暂存区 —— 移植必须覆盖什么，以及来自 theremin/chorale 工作（2026-08）、应作为*该栈中的行为*而非更多临时模式落地的想法。

[parity audit]: https://claude.ai/code/artifact/4ea45b32-a298-42ea-bcb4-1d2a7a567948

## 从运行时移植（审计 §03）

一个 16 状态机 —— Chill、LookAround、Wander、TurnInPlace、Zoomies、Startle、Stretch、Ruffle、Preen、Sneeze、Dance、GroundPick、Nap、BallPlay、Petted、Held —— 构建于：

- 一个驱动状态选择的**能量/心情模型**
- 用于 Wander 的**新颖度网格探索记忆**
- 带新鲜度门控的 **ToF 避障**
- 基于对比度的**惊吓**；**声音反应**（噪音 vs 人声），带自音频/自运动门控
- **玩球**（靠近 / 对齐 / 踢）、一个**小睡周期**、**抚摸反应**
- 进程内手柄↔自主切换（DpadRight 2 秒）、`--autonomous-max-speed`

它的输入现在都已在守护进程中存在：环境声音事件（步骤 2 —— 已记录，无消费者）、深度帧（步骤 3）、分类后的躯干帧障碍点（步骤 5）以及语音标签（步骤 2，"就绪并等待大脑步骤"）。`Held` 依赖于拿起检测，而该检测已被弃用 —— 决定是复活它还是丢掉该状态。

## 大脑免费获得的新输入（2026-08 工作）

theremin/chorale 步骤构建的、运行时大脑从未有过的东西：

- **附近的鸭子，按稳定 id** —— chorale 信标（`ChoraleBeacon`），在 BLE 地址轮换后存活（见 `docs/../memory`：绝不要以地址为键）
- **无需时钟同步的共享节拍**（`sounds::chorale::beat`）—— 鸭子间 ±20 ms
- **每个广播的 RSSI** —— 免费的粗粒度距离（近 / 远 / 接近中）
- **约 245 字节的扩展广播载荷余量**
- **一个实时合成器音色**（`sounds::Stream`）：运行时的音高/音量/元音，而不只是音库 wav
- **来自 ToF 的手距离**（`kinematics::hand::Tracker`）

## 行为想法，大致按每行魅力排序

**社交（BLE 在场 —— 新领域）：**

- **识别与问候** —— 维护一个已遇到的鸭子 id 的持久列表；对陌生人 `greet`，对朋友发出更温暖的声音，当朋友的信标变旧时发出 `peck`/叹息。友谊作为一个随时间改变问候的相遇次数。读起来像*记忆*；无需同步。
- **孤独 / 满足** —— 独处的鸭子偶尔叫唤；有伴的鸭子不叫。作为心情模型的输入，而非状态。
- **接近时的兴奋** —— 对一个已知 id 的 RSSI 上升 → 可见的期待。
- **马可波罗** —— 一只鸭子藏起来，另一只通过随着 RSSI 增长而更快嘎嘎叫来引导你。
- **跟随领头者** —— RSSI 保持间距，ToF 处理正前方的鸭子。
- **掌声 / 社交反馈** —— 一只鸭子做一段滚奏，附近的鸭子作出反应。
- **电话** —— 一条消息通过余量载荷在鸭子间跳跃，发生变异。
- **投票** —— 信标载荷中的偏好；多数选出群体的下一个行为。

**节拍同步的运动（在能展示的地方兑现同步工作 —— 不涉及扬声器）：**

- **群体点头 / 摇摆** —— 所有鸭子在共享节拍上同相；视觉同步容忍约 50 ms，而音频想要 20 ms。一小节的重拍上的群体姿势。康加舞队列。
- **Dance**（已是一个运行时状态）在有伴时变成*同步的*舞蹈。

**音乐的，超越 chorale：**

- **呼叫与应答** —— 对句；乐句之间的间隙隐藏同步误差，因此它比 chorale*更容易*且更像鸭子。
- **轮唱** —— 相同旋律，刻意的多小节偏移；偏移吸收误差。
- **各一个角色** —— 持续音 + 节奏性啄食 + 旋律。小扬声器做织体比做和声更好。

## 鸭子检测器（摄像头 + NPU）—— 想要的，等待 mediad

一个针对*我们自己的鸭子*的微型单类检测器：用于凝视与跟随的精确**方位**，这是 ToF 与 BLE 都给不了的。RK3566 有一个 0.8 TOPS INT8 NPU（`rknpu2` / `rknn-toolkit2`）；一个 320 输入的 YOLOv8n/11n 级模型应运行约 20–40 ms → 15–30 Hz，让 CPU 空闲。距离计算：IMX219 约 62° HFOV，一只 25 cm 的鸭子在 3 m 处约 25 px —— 房间尺度，即交互包络。

- **先门控：** 板子上有 NPU 驱动吗？（`dmesg | grep -i rknpu`）—— 厂商内核的 `rknpu2`，而非主线。以及 `/dev/rga` 用于免费的 NV12 缩放。让 mediad 从 ISP 主路径分流原始 NV12；检测器不得解码流式 MJPEG。
- **数据是项目，不是模型。** 鸭子视角的素材（机器人高度、机器人摄像头）由一个大型开放词汇模型自动标注，蒸馏到微型模型；来自 Open Duck CAD 的合成渲染用于尾部；硬负样本（橡皮鸭、白色印花）。
- **融合：** 视觉无法区分相同的鸭子 —— 摄像头 = 方向，ToF = 距离，BLE 信标 = 身份 + 在场。跟随领头者使用全部三者；"做事时互相看着对方" = 信标说*何时*，检测器说*何处*，`robot.look` 完成其余。
- 与 `tofd`/`pet-detect` 相同的架构：一个在 `robotd` 外的感知 worker，可安全杀死。在 mediad 移植期间修复占位的 IMX219 内参（审计 §04 TODO）。

## 移植的形态说明

- 在场、心情与共享节拍是**一个大脑的输入**，而非其旁的模式 —— chorale/theremin 作为显式模式增长是因为没有大脑可以挂载它们；当它落地时把它们折叠为状态/输入（"Petted" 之于 pet-detect 正如 "Sing" 之于一个听到的信标）。
- **chorale 最终成为一个自发事件，而非命令。** `robotctl chorale` 是工作台脚手架：一旦鸭子自主运行，一群在一起的鸭子应该*有时*自己突然唱起歌来 —— 一个被在场（且可能心情/能量）门控的低随机概率，就像 Zoomies 或 Dance 触发那样，而非用户启动的东西。故意罕见：一场意外的二重唱是一种愉悦，一个点唱机不是。机制几乎不变 —— 一个空闲信标的鸭子已经知道谁在附近，因此"决定唱歌"是又一次转换；`[chorale] accept` 作为同意门保留，决定一只鸭子是否可以加入。
- chorale 的同意规则可泛化：**任何社交的东西都是选择加入且关闭 = 不可见**（今天是 `[chorale] accept`；明天可能是一个 `[social]` 开关）。
- 识别/问候是正确的*第一个*行为：每行魅力最高、无需同步，且它演练 BLE 发现层 —— 仍受硬件怀疑的那部分。
